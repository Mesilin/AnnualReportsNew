Есть старая desktop программа на net 4.6.1? которая представляет из себя набор форм для ввода данных из которых потом строятся годовые отчеты региональных баз авиалесоохраны.
Ежегодно формы отчетов могут меняться. Иногда косметически - только заголовки столбцов, а иногда и могут появляться или удаляться новые столбцы. 
Программа дорабатывается, формы для ввода данных, их валидация, таблицы в БД мигрируются под новые данные.

Сейчас есть задача по реализации всего этого в виде подсисемы существующего asp net приложения на NET 6 (Основное приложение). 
Там уже есть часть исходных для отчетов данных и справочники.

Чтобы не переписывать в декабре пол приложения нужно сделать механизм хранения конфигурации форм в виде например json в БД Postgresql. 
Также нужно хранить правила валидации. например они могут звучать так: "Площадь лесов, фактически охраняемых в ведении субъектов РФ, не должна превышать общую площадь этих лесов" или так: "Сумма площадей зон лесоавиационных работ (гр. 3+4+5) должна быть равна общей площади земель лесного фонда (гр. 1)". Также нужно обеспечить межформенный контроль: Значение параметра в одном отчете должно быть например меньше или равно параметру другого отчета.

Примеры форм отчетов представлены в папке FormExamples. конвертировал их из doc.

Нужно сделать механизм хранения конфигурации форм отчетов (визуальный конструктор форм не нужен), конфигурации правил валидации.

Часть данных пользователи будут должны вводить вручную, 
часть данных будут браться из имеющихся на основной системе справочников, 
а часть данных нужно как-то получать из имеющихся, но разнесенных таблиц. Например в основном приложении хранится информация о пожарах и динамике их развития, налетах, но эти данные нормализованы.
Может создать представления с данными? Но тогда ежегодно их придется создавать новые под изменившиеся формы отчетов, да и основное приложение может менять модели. Может хранить в конфиге SQL запрос? И данные для отчета в конфиге брать из него? Тогда при смене модели запрос может падать, но мы можем хранить уже сформированные отчеты и отдавать их по запросу и тогда перегенерация не нужна. То есть идея в том, чтобы за текущий год можно было генерировать отчеты, а за предыдущие только читать ранее созданные.
Давай подумаем над архитектурой. Правильно ли я рассуждаю? Я хочу создать демо-веб приложение где можно будет отладить алгоритм. Нужно создать БД, таблицы с конфигом форм отчетов и правил валидации. Таблицы тестовых данных справочников (субъекты, авиаотделения, лесничества), Таблица с данными о пожарах. Затем нужен механизм генерации веб-страничек для ввода данных форм и проверки этих данных. Нужно отработать ручной ввод, выбор из справочников и вычисляемые значения (например количество пожаров в разрезе лесничеств).

Помоги сделать такое приложение на asp-net6.
